# Logs — 쓰는 법 · 보는 법

`_logs/`는 **다음 작업을 위한 기억**이다. 전체를 매번 읽지 않는다.

## 시작 전 (이 순서만)

1. `decision-log.md` → **「현재 유효 결정」** 표
2. `qa-log.md` → **「템플릿별 최근 결과」**에서 이번 slug
3. `failure-log.md` → 이번 작업 유형(L1·T1…) **카드만**
4. (이어서면) `change-log.md` **맨 위 최근 몇 건**

## 끝낸 뒤 (반드시)

| 무엇을 했나 | 어디에 적나 |
|-------------|-------------|
| 기준이 바뀜 (폭, 트랙, 납품 경로…) | `decision-log` **표 수정** + 날짜 섹션 추가 |
| 파일·기능 바뀜 | `change-log` 맨 위에 날짜 섹션 |
| 섹션/페이지 검수 | `qa-log` **표 한 줄 갱신** + 날짜 섹션 (1섹션 1건) |
| 같은 실수 다시 안 하려고 | `failure-log` **유형 카드에 한 줄** + 상세 날짜 섹션 |
| ZIP 자동 검사 | `wordpress-verify-log` (도구가 씀) |
| SEO/AEO/GEO 상태 | `decision-log` 표 또는 해당 slug 비고: **미실행 / 완료 / 의도적 생략** (`20` · `73`) |

## 적을 때 규칙

### decision
- 표 = **지금 통하는 것만**. 폐기된 결정은 표에서 빼고 히스토리에만 남김.
- 제목: `## YYYY-MM-DD — 짧은 제목`

### change
- **날짜순 유지** (최근이 위). 요약 bullet 3~8개.
- 오답/결정은 여기 길게 쓰지 말 것 → failure / decision으로.

### qa
- 표의 slug 행을 **이번 결과로 덮어쓴 다음** 본문 추가.
- 필수: 범위 · PASS/FAIL · 다음 주의 1줄.
- 섹션 단위 1건 (`20-harness-workflow`).

### failure (오답노트)
- **유형 ID** 고르기 (L1 레이아웃, L2 wrap, T1 정렬, G1 gap, B1 BG, M1 모바일…).
- 카드에: 증상 한 줄 · 하지 말 것 · 규칙 링크.
- 상세는 짧게. 장문은 규칙(`30`/`50`)에 이미 있으면 “규칙 봄”만.

## 금지

- 로그만 두껍게 쓰고 **규칙/QA 체크에 안 넣기** (재발 방지 실패)
- 관련 없는 옛 로그 전부 정독
- qa-log 없이 다음 섹션 진행

## 이 라이브러리에서

- `*.template.md` = **빈 골격** (프로젝트 `_logs/`로 복사해 채운다)
- `_variants/*.kmong.full.md` = 예전 실로그 참고용 (그대로 가져가지 말 것)

보안: 로그에 비밀값·토큰을 적지 않는다. `../SECURITY.md`
